VK public posts

A short Colab cell that reads recent public wall posts from one VK community through the official API. Built so I can inspect public text before deciding whether it belongs in any later pipeline — not to scrape the web.

Why it exists.

See the text before you train

Public walls are noisy. This cell prints dates and the first 280 characters so I can judge whether the content is even useful — before anyone talks about a dataset.

Stay inside the API

It calls wall.get on a public community screen name. No login-as-user flow, no private messages, no access-control bypass.

Keep the credential out of git

The notebook reads VK_TOKEN from a Colab secret. If the secret is missing, the cell stops. It does not fall back to a hard-coded key.

Stop before collection

It prints. It does not write a corpus file. A printed post is not a training set until that decision is made separately, with rights checked.

LimitThis is a public-read utility. It is not a crawler, it does not bypass access controls, and a printed post is not evidence that the text may be reused for training.

How to run it.

1. Add the secret

In Colab, create a secret named VK_TOKEN. The notebook reads it at runtime.

2. Pick a public community

DOMAIN is the screen name. The sample is ru_mash. Change it. Posts with no text are skipped.

3. Read ten posts

The cell prints date + first 280 characters for each public post returned by the API.

4. Decide later

If the text looks useful, that is a separate product or research decision — not this cell’s job.

The call.

DOMAIN = "ru_mash"  # public community screen name
COUNT = 10
token = userdata.get("VK_TOKEN")
vk = vk_api.VkApi(token=token).get_api()
posts = vk.wall.get(domain=DOMAIN, count=COUNT)
